- `enabled==true / running==true`；`queue_monitor(10) / idle_detector(15)` 已注册，`running` 为真；`run_count` 到点递增但不推送（监测源未接入，预期行为）。
- **核心缺陷（真实确证）**：`ticks` 以 **+2/60s**（设计 +1/60s）。
  - 根因：**FastAPI 0.139.2 / Starlette 1.3.1 把 `@router.on_event("startup")` 触发 2 次**
    （最小复现：注册 handler=1、实际运行=2）。
  - 插桩确认 `_start_background_scheduler` 执行 2 次 → 同一 scheduler 单例跑 2 个 `run_loop`
    → `ticks` 计数 2× → **queue_monitor 实际约每 5 分钟、idle_detector 约每 7.5 分钟触发（配置周期减半）**。
- 隔离验证：单个 `Scheduler.run_loop(tick_seconds=60)` 在无 app 框架下 = 干净 60s 节奏（+60.0s/+60.0s），
  **调度核心与绝对时刻对齐是正确**的；缺陷纯来自框架 `on_event` 双触发。
- **判定**：**「检测周期≤30s / 调度误差≤5s」在当前依赖版本下不能按设计口径达成**（真实缺陷，非代码串通）。
